# Приглашение на свадьбу

Одностраничное приглашение Евгения и Карины — 29 августа 2026 года.

Главное условие проекта: на выходе **один самодостаточный HTML-файл** без
единого внешнего запроса. Он открывается двойным кликом с диска, работает
офлайн, живёт под строгим CSP и заливается на любой хостинг. Отсюда все
остальные решения.

## Как это устроено

Nuxt используется только как система компонентов и пререндера, а не как
обычное приложение:

- `features.noScripts` выкидывает клиентский бандл;
- `inlineStyles` вклеивает CSS прямо в `<style>`;
- вся интерактивность живёт в `app/assets/invite.js` и попадает в HTML
  инлайн-тегом (см. `app/app.vue`);
- `scripts/bundle.mjs` собирает финальные файлы и **проверяет**, что в них не
  осталось ни одной внешней ссылки на подресурс. Если осталась — сборка падает.

Данные приглашения лежат в одном месте — `app/utils/wedding.ts`. Компоненты
только отображают их, а часть полей уезжает в браузер JSON-блоком, чтобы
`invite.js` не дублировал конфиг.

```
app/
  app.vue              подключение стилей, SEO, инлайн-скрипты
  pages/index.vue      порядок секций
  utils/wedding.ts     ВСЕ данные: даты, места, тексты, контакты
  assets/invite.js     интерактив: конверт, отсчёт, ответ гостя
  assets/css/main.css  палитра, типографика, общие анимации
  components/          секции и декор
scripts/
  bundle.mjs           постсборка и проверка самодостаточности
  serve-dist.mjs       локальный просмотр готовой сборки
```

## Запуск

Нужен **Node 20 или новее** — на Node 18 `nuxi` падает.

```bash
pnpm install
pnpm dev            # разработка: http://localhost:3000
pnpm build:one      # сборка одного файла → dist/
pnpm preview:dist   # посмотреть готовую сборку: http://localhost:4173
```

`pnpm build:one` кладёт в `dist/` два файла:

- `invitation.html` — самодостаточная страница, её и отправляют гостям;
- `artifact.html` — то же содержимое фрагментом, для публикации артефактом.

## Настройка

Всё редактируемое — в `app/utils/wedding.ts`: имена, дата и время церемонии,
локации со ссылками на карты, программа дня, трансфер, суперигра, текст
просьбы и заготовки ответа.

Дата церемонии задана с жёстким смещением Минска (`+03:00`), иначе гость из
другого часового пояса увидел бы сдвинутый обратный отсчёт.

### Ответы гостей в Telegram

Скопируйте `.env.example` в `.env` и заполните два значения — страница начнёт
отправлять ответы сама:

```bash
cp .env.example .env
```

Как получить токен и chat id — написано в самом `.env.example`. Если оставить
поля пустыми, кнопка ответа просто копирует текст и открывает чат: страница
остаётся рабочей.

> **Важно.** Значения из `.env` вклеиваются в собранный HTML, который вы
> разошлёте гостям, и видны в исходнике страницы. `.env` прячет их только от
> репозитория. Заводите отдельного бота под приглашение, а после свадьбы
> отзывайте токен: `@BotFather` → `/revoke`.

## Публикация

Приглашение можно просто отправить файлом: `dist/invitation.html` работает
с диска, из мессенджера и с любого хостинга.

Если нужен адрес в интернете — проект настроен под Vercel, все параметры
сборки лежат в `vercel.json`, руками ничего задавать не нужно:

1. Vercel → **Add New → Project** → импортировать репозиторий `wedding`.
2. В **Settings → Environment Variables** добавить две переменные для всех
   окружений (иначе кнопка ответа просто вернётся к копированию текста):

   | Имя | Значение |
   | --- | --- |
   | `VITE_RSVP_BOT_TOKEN` | токен бота |
   | `VITE_RSVP_BOT_CHAT_ID` | ваш chat id |

3. **Deploy**. Дальше каждый пуш в `main` пересобирает страницу сам.

Сборка на Vercel идёт той же командой `pnpm build:one`, а значит проходит и
проверку самодостаточности: если в страницу попадёт внешний запрос, деплой
упадёт, а не выложит поломанное приглашение.

### Фото пары

В `app/components/TheHero.vue` есть заготовленное место. Внешние картинки
использовать нельзя — вставляйте снимок как data-URI, инструкция там же
в комментарии.

## Что должно продолжать работать

Эти свойства легко сломать незаметно, поэтому стоит проверять после правок:

- **ноль внешних запросов** — за этим следит `scripts/bundle.mjs`;
- **страница без JavaScript** — конверт не показывается, но всё содержимое
  читается; поэтому секции прячутся под анимацию только при живом скрипте;
- **тёмная тема** — системная и явная (`data-theme`), обе на одних токенах;
- **`prefers-reduced-motion`** — движение выключается, красочность остаётся;
- **страховка конверта** — если основной скрипт не доберётся до заставки,
  бутстрап в `<head>` снимет её сам через пять секунд.
